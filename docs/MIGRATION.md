# Migration plan

## Dev → Prod path

1. **Dev**: Postgres in Docker (`docker compose up -d`), Prisma managed schema.
2. **Staging**: Managed Postgres (Neon/Supabase) + same Prisma migrations.
3. **KSA data-residency prod**: re-deploy to a Saudi region (STC Cloud / NEOM
   or self-hosted Postgres). The ORM layer is provider-agnostic, so only
   `DATABASE_URL` changes — zero app-code change required.

## Running migrations

```bash
# Dev loop (creates & applies a new migration from schema drift)
pnpm db:migrate

# Apply baseline vector column (required once, after first migration)
# Auto-applied because it lives under prisma/migrations/0001_add_vector_column/

# Production deploy
DATABASE_URL=... pnpm -F @elp/db migrate:deploy
```

## Migration ordering

1. `0000_init` — generated by Prisma on first `db:migrate`; creates all
   relational tables + enums.
2. `0001_add_vector_column` — hand-written: adds `vector(1024)` column and
   HNSW + GIN + trigram indexes. Kept separate because Prisma can't yet
   model pgvector natively.

## Schema changes policy

- **Additive** (new column/table): safe — Prisma generates a forward-only
  migration; no data loss.
- **Destructive** (rename/drop): always craft the migration by hand — do not
  use `prisma db push` in production. Pattern: add new column → backfill →
  switch reads → drop old column in a follow-up migration.
- **Enum changes**: use `CREATE TYPE … AS ENUM … RENAME`; Prisma handles most
  additions but renames require manual SQL.

## Data migration

- Products and manufacturers are loaded via CSV (`scripts/import-products.ts`).
- The importer is idempotent keyed on `product_code` and `manufacturer_name`.
- Re-running the importer updates existing rows; links are upserted on the
  composite key `(product_id, manufacturer_id)`.

## Index strategy

| Table | Index | Purpose |
|---|---|---|
| products | category, industry_segment, criticality_level, approval_status | filter lists |
| products | product_name_en/ar (trigram GIN) | fuzzy search |
| manufacturers | is_local, country, manufacturer_type, verification_status | scope + filter |
| manufacturers | manufacturer_name (trigram GIN) | fuzzy search |
| document_chunks | embedding (HNSW, cosine) | ANN retrieval |
| document_chunks | metadata (GIN JSONB) | hybrid filter+semantic |
| audit_log | entity, user_id, created_at | audit queries |

## Backup / DR

- Nightly `pg_dump` to S3 bucket (out of scope of Phase 1 but the
  `data_residency` design does not block it — use the same S3-compatible
  storage already configured via `S3_*` env vars).
